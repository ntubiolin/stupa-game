## Frozen first chapter interface
- `createChapterDirector(ctx)` returns/assigns `ctx.chapters`; constructed AFTER storyDirector, BEFORE story.start(). `getState()` => `{activeChapterId, chapters:{pharping:{checkpointId,completed}} , replaying, readOnly}` (snapshot; missing entry means not started). `canStart(id)`; async `start(id,{replay=false}={})`; `signal(name,{checkpointId})` => boolean; `exit()` => boolean; `dispose()` cancels pending loads/listeners. Replay only for completed chapters, transient, never save/regrant progress. Exit keeps checkpoint but activeChapterId null. start resumes current chapter or first checkpoint. Only pharping enabled initially; later chapter registry additions separately tested.
- Runtime supplies `ctx.prepareChapter(id,checkpointId)` => Promise<boolean> before start/resume commits. It loads/verifies scene without changing durable checkpoint, returns false on failure. `start()` uses session token; failed/cancelled prepare never activates or commits. On boot runtime calls `chapters.resume()` which prepares current saved active chapter then emits state (no forced re-start/reset). If prep fails keep durable checkpoint and expose retry/exit.
- StoryDirector owns complete story snapshot; add `getJourney()` snapshot and `commitJourney(journey)` boolean backed by save atomic section write; chapterDirector never registers a second serializer. Save root v2 unchanged, story internal version2 migrates v1 preserving all existing fields. Unknown newer story/root versions cannot be written. Current Demo beats remain unchanged. Old complete needs explicit Continue.
- Save adds `commitSection(section,data)` => `{ok:boolean,error?:string}` with in-memory rollback on failure; `flush()` returns boolean (backwards compatible ignored return). Keep dirty writes for retry; merge latest untouched sections in BOTH scoped story and default adventure writes. Preserve root reset/import semantics deliberately; don't blindly resurrect removed sections. `getStatus()` => `{ok,error?}` for UI. No false saved status. Test failures, older runtimes/newer fields, unknown sections, multiple tabs/instances.
- `story:chapter-change` `{chapterId,checkpointId,replaying}` emitted after successful state commit (or transient replay); `story:chapter-exit` emits after exit. Original Demo events preserved. guard synchronous reentry; stale checkpointId and duplicate signals rejected. Chapter schema validates ids/types/length and canonical completion; debug skipTo doesn't grant chapter completion.
- Ordered pharping checkpoints/signals: spring1/`spring:clear`, spring2/`spring:clear`, channel1/`channel:clear`, channel2/`channel:clear`, manuscript/`manuscript:take`, cave/`manuscript:return`, shadow/`shadow:observe`, release/`shadow:release`, rain/`rain:return`, diary/`diary:read`, complete/(none). chapter record complete when diary:read accepted.
